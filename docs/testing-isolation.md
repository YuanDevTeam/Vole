# 服务端测试隔离

普通协议、原站和故障对端运行在自有隔离容器。Apple 真机测试使用显式绑定私有 LAN 地址的自有 Mac 原站，HTTP／MITM 业务经真实 Network Extension。Mac socketpair 模拟保留实际 Core／netstack，单独记录模拟包路径与容器对端。直接 LAN 对照保持 Core 和 Network Extension 停止。

宿主离线检查限于编解码、内存 I/O、临时文件与配置；涉及外部对端的验证使用上面的隔离环境。

编排、对端下载和压力测试由独立容器测试工具管理，执行时显式传入
`--source vole=PATH`。Vole 编译不依赖测试工具 checkout。

## 执行要求

1. 容器带任务所有权标记并使用 NAT/bridge 网络。需要端口发布时只使用本次运行的自有端口和已声明的测试地址，保留宿主 VPN、路由、DNS、防火墙及其它任务资源。
2. 对端使用官方最新稳定发行二进制和官方稳定镜像，记录实际版本。保留 Mihomo 回环
   保护及第三方默认 socket 行为。仅 Caddy 可按需使用官方 xcaddy 构建并注明来源。
3. 地址来自容器网络；配置、证书和凭据放临时目录，fixture 只读挂载，日志有界且脱敏。
4. 启动前登记资源所有权，成功、失败、超时和中断均停止并等待本次容器退出。
   先保存文字结论，再删除本次临时容器、网络和中间产物；已验证的共享依赖缓存独立保留。
   清理前复查资源归属；清理失败时保留必要现场并记录错误。
5. 结果记录实际命令、环境、输入、流量、指标、失败、停止和清理状态。Vole 互通和业务完整性验收校验双向内容；认证拒绝由原站观测确认。Mihomo 容量参考按[实际收发口径](acceptance.md#压力与性能)计量。
6. CLI、原生 Invoke/FFI、协议、DNS、生命周期和压力的网络验收业务统一经过真实 TUN。
   使用隔离的负载网络命名空间、真实 raw-IP fd，并校验 TUN 流量和回收；
   Controller 仅作管理入口。上述 socketpair 诊断独立记录其模拟边界；纯内存、离线和编译检查不要求 TUN。

互通、压力和设备验收分别执行，范围见 [验收边界](acceptance.md)。具体对端与用例参数
与实测结论统一由 benchmark 工程维护。
