# 服务端测试隔离

普通协议服务端、TCP/UDP/HTTP/DNS 原站、故障注入服务端和提供监听入口的对照客户端，
均在隔离容器中运行。以下明确授权的 Apple 测试使用宿主对端，其余测试不因容器不可用而扩大范围：

- Apple 真机 HTTP／LAN 测试的合成原站直接运行在 Mac，绑定显式的私有 LAN 地址；HTTP／MITM 验收仍经过真实 Network Extension/TUN，LAN 直连对照明确保持 Core／NE 关闭。
- macOS 并发诊断使用 socketpair 模拟包 I/O，连接自有 loopback 原站，复用实际 Core／netstack 路径。此结果属于模拟诊断，不代替真实 TUN、设备、吞吐或内存验收。

宿主对端和测试进程登记精确子进程、监听地址、二进制与输入身份，结束后停止并 join。
全部路径保留宿主 VPN、路由、DNS、防火墙及无关资源。纯内存、编解码和离线配置测试可在宿主执行。

编排、对端下载和压力测试由独立容器测试工具管理，执行时显式传入
`--source vole=PATH`。Vole 编译不依赖测试工具 checkout。

## 执行要求

1. 容器带任务所有权标记，使用 NAT/bridge 网络；不发布宿主端口，不修改宿主 VPN、
   路由、DNS 或防火墙，也不清理其他任务的容器和网络。
2. 对端使用官方最新稳定发行二进制和官方稳定镜像，记录实际版本。保留 Mihomo 回环
   保护及第三方默认 socket 行为。仅 Caddy 可按需使用官方 xcaddy 构建并注明来源。
3. 地址来自容器网络；配置、证书和凭据放临时目录，fixture 只读挂载，日志有界且脱敏。
4. 启动前登记资源所有权，成功、失败、超时和中断均停止并等待本次容器退出。
   先保存文字结论，再删除本次临时容器、网络和中间产物；已验证的共享依赖缓存独立保留。
   清理前复查资源归属；清理失败时保留必要现场并记录错误。
5. 结果记录实际命令、环境、输入、流量、指标、失败、停止和清理状态。双向业务应校对内容，
   认证拒绝应确认原站未收到被拒绝的业务，客户端超时本身不能证明拒绝生效。
6. CLI、原生 Invoke/FFI、协议、DNS、生命周期和压力的网络验收业务统一经过真实 TUN。
   使用隔离的负载网络命名空间、真实 raw-IP fd，并校验 TUN 流量和回收；
   Controller 仅作管理入口。上述 socketpair 诊断独立记录其模拟边界；纯内存、离线和编译检查不要求 TUN。

互通、压力和设备验收分别执行，范围见 [验收边界](acceptance.md)。具体对端与用例参数
与实测结论统一由 benchmark 工程维护。
