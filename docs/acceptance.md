# 验收边界

只报告实际执行的检查。结果记录在对应 CI、PR 或 benchmark 运行中，本文维护验证范围。

兼容验收遵循 [Mihomo 兼容原则](mihomo-compatibility.md#兼容原则)：验证与 Mihomo listener 和官方协议 server 的互通，性能优化综合评估吞吐、CPU、内存和丢包率的收益与代价。字段对照用于记录支持范围与差异，不要求逐字段行为相等。性能达标须依据当次明确的内存预算、目标负载及实测结果判断，不能仅凭连接成功或配置解析通过。

| 层次 | 验证内容 |
| --- | --- |
| 离线 / 纯内存 | 配置、协议编解码、取消、生命周期、内存与 FFI 所有权 |
| 平台编译 | 各目标构建、CLI 基本运行、库文件和发布归档 |
| 原生消费者 | C/Swift/JNI 等真实宿主的加载、调用与资源释放 |
| 容器互通 | Mihomo listener 与官方协议 server、真实双向流量、认证、支持模式的 UDP 与关闭行为 |
| 压力 | 实际吞吐、CPU、内存峰值、丢包、DNS 完成数及退出清理 |
| 设备 / 发布 | 真机 TUN、物理出口、权限、生命周期、签名安装及商店要求 |

协议互通先验证握手、认证、双向数据、关闭与资源清理。吞吐、CPU、内存和丢包率独立记录，
不以压力阈值判定互通失败；全部互通完成后，再单独进行压力验收与性能优化。

编译不替代原生消费者或设备验证；模拟器、Wintun 与 UWP 分别验收。
Linux RSS 不等于 Apple Network Extension physical footprint。
性能结果须同时给出输入、目标负载和实际负载，保留失败与丢包情况。

## 性能采纳标准

### 内存与环境

- macOS 模拟记录独立 Core worker 的 `phys_footprint`。iOS 和 tvOS 真机记录整个 Network Extension 的 `phys_footprint`，包括 Core、宿主桥接和扩展运行时。Apple 验收预算统一为 **≤45 MiB（47,185,920 字节）**。
- Linux 记录 RSS，Android、Windows 记录各自可取得的进程内存指标，均用作参考。记录测量进程、指标、启动、活动窗口、排空及停止覆盖范围。跨平台结果须按实际指标解释。
- 真机、真实 TUN 和 Mac socketpair 模拟分别报告。物理设备的最终验收使用实际设备、权限和连接条件。

### 压力与性能

Mac 综合模拟分别执行 JS 和原生规则加 JS 的窗口，覆盖明文 HTTP、HTTPS H1/H2、适用的 UDP 和 DNS。HTTP 准入按完整送入的请求正文确认，已准入业务的最终改写、内容归属、DNS、活动及排空窗口和资源清理分别核对。

Linux 真实 TUN 压力按协议覆盖 TCP、UDP 和混合业务。Vole TCP 验证交付与内容，UDP 丢包按实际发送和唯一有效接收计量。吞吐按活动窗口计量，交付丢包在固定排空后计算，保留上下行原始计数。

默认目标未达标时，对匹配协议和负载使用官方 Mihomo 作为容量参考。只比较实际收发的业务字节和数据报交付比例；未发送量、CPU、RSS 和传输诊断独立记录。适用负载档位、相对性能门槛和阶段关闭证据由 benchmark 工程维护。Vole 的正确性、测量和正常停止要求独立验收。

### 采纳优化

比较相同输入、负载和测量口径的普通 Release 构建，验证受影响的组合，分别记录性能和正确性。压力报告、对照执行细则和历史结果由 benchmark 工程维护。

- 吞吐、CPU、内存和丢包率都允许渐进式改进，不要求一次修改达到全部目标、各项同步改善或单项绝对不退步，不设单次改善幅度下限。不固定指标优化顺序，按实测瓶颈和综合收益选择下一步。
- 允许指标之间的合理取舍，结合改善幅度、代价、实际完成量和运行间波动评估；综合收益为正的阶段性改进可以采纳。减少实际负载或业务未完成导致的 CPU、内存下降不能算作优化收益。
- 公共路径改动复测受影响的已通过范围。各测量窗口保留实际完成量、错误和清理状态；旧证据仅用于其原运行身份。
- 过载压力分别记录吞吐、CPU、丢包、实际交付与资源回收，并按声明的平台内存口径和实际窗口验收。

过载保护应遵循[运行时资源策略](runtime-resource-policy.md)的资源所有权、局部容量、取消和同步 Stop 边界。

核心测试入口见 [tests](../tests/README.md)，平台与发布入口见 [scripts](../scripts/README.md)。
网络互通和压力由独立容器测试工具执行，结果与结论统一保存在 benchmark 工程，
遵守 [测试隔离](testing-isolation.md)。设备要求见 [TUN 平台层](tun-platform.md)
与 [Windows VPN](windows-vpn.md)。
