# 验收边界

只报告实际执行的检查。结果记录在对应 CI、PR 或 benchmark 运行中，本文维护验证范围。

兼容验收遵循 [Mihomo 兼容原则](mihomo-compatibility.md#兼容原则)：验证与 Mihomo listener 和官方协议 server 的互通，以 Vole Core 的内存优化和吞吐达标为第一目标。字段对照用于记录支持范围与差异，不要求逐字段行为相等。性能达标须依据当次明确的内存预算、目标负载及实测结果判断，不能仅凭连接成功或配置解析通过。

| 层次 | 验证内容 |
| --- | --- |
| 离线 / 纯内存 | 配置、协议编解码、取消、生命周期、内存与 FFI 所有权 |
| 平台编译 | 各目标构建、CLI 基本运行、库文件和发布归档 |
| 原生消费者 | C/Swift/JNI 等真实宿主的加载、调用与资源释放 |
| 容器互通 | Mihomo listener 与官方协议 server、真实双向流量、认证、支持模式的 UDP 与关闭行为 |
| 压力 | 实际吞吐、CPU、内存峰值、丢包、DNS 完成数及退出清理 |
| 设备 / 发布 | 真机 TUN、物理出口、权限、生命周期、签名安装及商店要求 |

协议互通先验证握手、认证、双向数据、关闭与资源清理。吞吐、CPU、内存和丢包率独立记录，
不以压力阈值判定互通失败；全部互通完成后，再单独进行压力验收与性能优化。

编译不替代原生消费者或设备验证；模拟器、Wintun 与 UWP 分别验收。
Linux RSS 不等于 Apple Network Extension physical footprint。
性能结果须同时给出输入、目标负载和实际负载，保留失败与丢包情况。

## 性能采纳标准

所有平台与构建使用统一的内存策略和 benchmark 预算，内存统一使用 MiB：

- 内存硬门槛：**≤45 MiB（47,185,920 bytes）**。
- 常规压力优化目标：**≤40 MiB（41,943,040 bytes）**。

内存策略不按平台或编译模式切换，CLI 与 FFI 共用同一实现。

真实 iOS/tvOS VPN 扩展仍以整个 Network Extension 进程的 physical footprint 验收，
包含 Core、宿主桥接与扩展运行时。
45 MiB 是项目验收预算，不声明为各设备的系统限额，也不能只计算 Rust heap。
Linux 压力使用 RSS；Linux 结果只作优化筛选，不替代真机扩展验收。
其他平台记录承载 Core 的整个后台进程及实际指标口径，排除独立负载客户端和原站。
不同平台和测量指标的数值不直接混合排名。

定速压力使用既有 Linux 原生 TUN 环境。冷启动、配置和 GeoData 更新、负载、收尾及
Stop 都应覆盖；未执行的生命周期场景单独标明，不从一次压力结果推导。
测试执行完成不代表达到验收门槛。

性能对照使用相同输入、负载和重复次数的普通 Release 构建，分别比较吞吐/QPS 中位数
与同平台进程内存峰值。Linux 保留原压力负载和 RSS 观察逻辑，覆盖 exec 至退出/reap，
包括启动、负载、drain 和 Stop；heaptrack 等仪器开销、tracked heap 和 wait4 读数
不能替代这一验收口径。

- 内存占用是第一优先级，协议数据正确性、取消与资源清理必须保持。超过 45 MiB 必须继续优化，不能用吞吐改善抵消。
- 不要求一次修改达到最终目标。只要方案可以降低内存，就可以在相同输入和负载下逐项验证、采纳，通过多个方案积累达到目标；超限样本仍记为未达标。不设单次改进幅度下限。
- Linux 定速压力在 **1 Gbps** 下有效吞吐须 **≥990 Mbps**，UDP 丢包率须 **≤0.2%**，同时满足数据、实际负载到达和 DNS 完成要求。
- **2 Gbps** 用于内存过载验收，内存须 **≤45 MiB**，目标 **≤40 MiB**；吞吐、CPU 和丢包率只记录，不设吞吐及丢包门槛。允许通过掐连接、丢包、断连和限制队列大小等方式保护内存。仍须完成真实 TUN 的完整压力窗口，并验证已接收内容、源地址、观测有效性和退出清理；提前结束或没有实际流量不能代替压力验收。
- UDP 丢包率以实际发送与接收的包数计算，按上下行发送包数加权汇总，同时保留两个方向的独立计数。丢包在固定收尾后统计；吞吐仅统计活动窗口，不把漏发算作丢包。iOS/tvOS 吞吐负载根据真机与链路能力校准，内存预算保持一致。

数据有效性、实际完成量、负载到达、CPU、UDP loss、DNS 完成数、测量有效性及退出/join/资源清理分别记录。2 Gbps 下的超时、丢包、断连和未完成量保留原始状态，不因允许过载保护而改签为完整交付；错误内容或源地址仍使验收失败。测量成功不等于业务成功，编译、配置解析或连接成功不代替压力验收。历史结果保留当时语义，不追溯改签。

过载保护应遵循[运行时资源策略](runtime-resource-policy.md)的资源所有权、局部容量、取消和同步 Stop 边界。
